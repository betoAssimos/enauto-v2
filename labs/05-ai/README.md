## 5.2 — AI-assisted code development

This whole repo is the applied example. Two concrete mechanics enforced throughout, both from `master_context.md` §4:

1. **The `# SUGGESTION: generated by Claude` marker** — every AI-authored line lands tagged, reviewed, then the tag is stripped once Beto signs off. Live example from this session: [`labs/04-operations/TIG/mdt_config_rest.py`](../04-operations/TIG/mdt_config_rest.py) — the receiver IP was wrong for this environment (`192.168.1.251` vs. the actual clab bridge `172.30.30.1`), fixed and marked, unreviewed as of this commit.
2. **The 4Ds loop (§3)** — Delegation (AI drafts, Beto validates), Discernment (AI's output is challenged, not trusted), Diligence (nothing lands without a live verification step) — is why today's TIG rebuild ended in a live InfluxDB query proving data flow, not just "the script ran without errors."

## 5.3 — Security risks of AI automation

Each risk mapped to the repo control that mitigates it — these aren't abstract, they're rules already enforced in `master_context.md` §4:

| Risk | Mitigation in this repo |
|---|---|
| AI hallucinates a device output, API response, or library signature | Anti-hallucination rule: state uncertainty, verify live, tag `[Likely]`/`[Guessing]` until confirmed |
| Credentials pasted into a prompt or committed alongside AI-drafted code | `.env` gitignored, `secrets.example.env` shows names only, no hardcoded creds rule |
| AI-suggested script writes to a real device/controller unreviewed | Dry-run default + `--apply` gate on every write-capable script |
| Blind trust in AI-authored automation logic | Discernment — Beto validates every output; AI is a drafting tool, not an authority |
| AI-generated code silently merged without traceability | The `SUGGESTION` marker — see 5.2 above — makes AI authorship visible until reviewed |
